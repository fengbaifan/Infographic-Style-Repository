# 案例录入与知识回写规范 · Case-to-Theory Protocol
**适用于 02 全部市场表现标签与 01 五种基础类型**｜V1.0｜2026-11-19

## 一、不可违反的类型学规则
- **五种基础组织逻辑是唯一基础类型学**：编年型、层级型、编目型、字母表型、地理图型。
- 每张图一份正式案例卡，`primary_logic` 从五种中**必选且仅选一项**；根据**最主要的信息组织关系**判定，不根据图面模板。
- `presentation_tags` 可多选，例如 Mixed Charts、Informational/List、Timeline。标签仅帮助设计检索、行业沟通和市场化产品制作，**不得被统计为第六、第七种基础类型**。
- 组合图形若同时涉及多种组织关系，可在 `auxiliary_logics` 描述其他四类的局部作用；不改变主归属。若主归属证据不足，标注 `待分类` 且**不进入正式案例索引**，补足证据后归档。
- **01 不放图片**，仅保存论证文本和指向 02 具体案例的相对链接；**02 存放原图、图片版权/来源和所有逐图证据**。

## 二、案例文件与图片保存
建议在 `02-信息图形类型案例/案例记录/` 内按案例 ID 存：
- `CASE-0001-题名.md`：一张作品一份分析，兼记分析版本；
- `assets/CASE-0001-original.png` 或相应原始扩展名：仅当实际收到并有保存权限时保存；
- 可选 `assets/CASE-0001-detail-01.png`：裁切局部，须在说明中关联原图。
不要把没有取得的图像写入仓库，不要用示意图冒充原始案例。文件名及实例均以真实素材为准。

## 三、标准案例卡（复制下列字段创建新文档）
```yaml
case_id: CASE-0001
title: 待填真实作品名称
date_reviewed: YYYY-MM-DD
source_title: 待填
source_url: 待核实
creator: 待核实
image_path: 待上传
image_rights: 待核实
primary_logic: 待分类 # 核验后仅可填：编年型|层级型|编目型|字母表型|地理图型
primary_logic_evidence: 待填来自原图的具体组织证据
auxiliary_logics: [] # 可选；只能选五大中其他类型
presentation_tags: [] # 如 Mixed Charts|Informational/List|Timeline
evidence_status: pending_original
version: 0.1
```

案例正文必须包含：
- **原图可见事实**：能直接看到的标题、节点、图表、符号、标尺、关系；与猜测严格区分。
- **A 数据基本逻辑**：最小记录单位、主导关系、主要字段、有没有数值与阶段依赖。
- **B 统计与计算**：若存在图表，列出其计算、口径、坐标/尺寸映射；没有统计时如实写“无须数值统计”。
- **C 视觉编码**：逐项检查点、线、面、体、符号、色彩、文字；比较真实关系与视觉修辞。
- **D 数据／信息架构**：建立推定字段表，区分“图中有证据的字段”与“实现时建议的字段”；写明可转换的 Excel 行列结构。
- **E 视觉叙事架构**：视线起点、整体路径、重要转折、故事结论；识别图形是否诱导错误因果/比例。
- **判断与反例**：说明为何主归属是五类之一、为什么排除其他四类为主归属。
- **可迁移规则/例外**：哪些做法具有泛化条件，哪些仅属于该作品风格。

## 四、案例驱动更新流程
1. **验证原图**：有可读原始图和基本来源；记录不可读处，不能猜。
2. **分类**：由数据关系确认唯一五类主归属，再附加市场形式标签。
3. **逐图抽取 A–E**：至少找出每个维度一条可核实证据，空缺标注“未知”。
4. **对照已有理论**：将观察结果标记为“支持”“反例”“边界例外”“待验证”四种证据状态。
5. **更新 02**：写入案例卡；修改相关市场表现形式说明，加入具体案例链接与新总结。
6. **回写 01**：把**可复核、可迁移**的新增关系、统计限制、编码规则、叙事方法写回对应的**五大主类型说明文件**，在文字旁标明案例链接。不要因为看到一个特殊案例，就重命名五大基础类型。
7. **更新索引与版本记录**：索引双入口更新同一案例；Git 提交记录简述“新增证据、何处调整、是否修订定义”。

**更新节奏**：每次用户提供并要求分析新案例时，在同一次任务里完成案例分析及适用的文档修订；Git 仓库不具备无需新任务即可后台实时自更新的能力。

## 五、质量审查与冲突处理
- 检查原始图像与推断是否分离；数值、色彩、图形、时间、地理数据有无误读。
- 检查五大基础主归属是否唯一且可追溯，表现标签是否误入类型学。
- 检查统计计算与视觉编码一致；如图符重复应写明每个代表的量，地图图形要有正确空间键。
- 多个案例发生冲突时，不“多数投票”简单覆盖：先核实案例主题、数据结构和应用目的，必要时将条件分开写入 01 的判据与边界。
